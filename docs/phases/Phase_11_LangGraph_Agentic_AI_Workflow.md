# Phase 11 — LangGraph Agentic AI Workflow

## 1. Objective

Build the SCOPE agentic AI workflow using LangGraph.

The workflow coordinates ML predictions, RAG retrieval, evidence management, validation, and report generation.

## 2. Business Problem

A supply chain analyst may need to investigate a potentially disrupted order.

The investigation may require:

- Predicting late-delivery risk
- Estimating delivery duration
- Identifying unusual order patterns
- Retrieving supplier or policy documents
- Collecting supporting evidence
- Validating the findings
- Producing an evidence-grounded report

SCOPE should coordinate these components in a controlled workflow.

## 3. Agent Architecture

Recommended workflow roles:

### 1. Planner

Responsibilities:

- Understand the user query.
- Identify the relevant order, vendor, or supply chain entity.
- Select appropriate analytical tasks.
- Create an investigation plan.

### 2. Data Analyst

Responsibilities:

- Call classification models.
- Call regression models.
- Retrieve segmentation results.
- Retrieve anomaly scores.
- Retrieve forecasts where relevant.

### 3. Document Researcher

Responsibilities:

- Query the RAG service.
- Retrieve relevant document chunks.
- Preserve source and page references.
- Report when relevant evidence is unavailable.

### 4. Report Writer

Responsibilities:

- Combine verified analytical findings.
- Organize the report.
- Link factual claims to evidence.
- Clearly distinguish predictions, observations, and assumptions.

### 5. Checker

Responsibilities:

- Validate source references.
- Validate numeric claims.
- Check claim-to-evidence links.
- Identify unsupported content.
- Request correction or review when necessary.

The Evidence Ledger remains a separate database-backed service. It is not an agent.

## 5. LangGraph State

Define a structured state schema.

Suggested fields:

- `user_query`
- `entity_id`
- `investigation_plan`
- `data_findings`
- `document_findings`
- `evidence_ids`
- `draft_report`
- `validation_findings`
- `workflow_status`
- `final_report`
- `error_messages`

Use typed state definitions and validated inputs.

Avoid putting unnecessary large document contents into the state. Prefer IDs and references where possible.

## 6. Node and Tool Implementation

Create separate LangGraph nodes for:

- Planning
- Data analysis
- Document retrieval
- Evidence registration
- Report generation
- Validation
- Human review or correction

Expose existing ML and RAG modules as controlled tools or service functions.

Do not duplicate the business logic of ML models or RAG inside agent prompts.

## 7. Routing and Conditional Edges

Use conditional routing based on the investigation plan.

Examples:

- If the user asks about a specific order, retrieve its analytical record.
- If the question concerns a supplier contract, invoke RAG retrieval.
- If the question concerns future risk, invoke the relevant prediction module.
- If evidence is insufficient, mark the investigation as incomplete.
- If the Checker detects critical issues, route to correction or human review.

Do not execute irrelevant tools simply because they are available.

## 8. Reliability and Safety

Implement:

- Input validation
- Timeouts
- Bounded retries
- Error handling
- Maximum workflow steps
- Tool permission boundaries
- Structured outputs
- Audit logging

Do not allow the agent to execute arbitrary SQL generated by the LLM.

Use parameterized queries and approved repository functions.

The agent must not invent order IDs, vendors, documents, model metrics, or citations.

## 9. Human Review

For high-impact or unsupported conclusions:

- Mark the workflow as `needs_review`.
- Record the reason.
- Preserve the evidence and draft.
- Allow an authorized reviewer to approve or reject the report.

Do not claim that a human has approved a report unless an actual approval event is recorded.

## 10. PostgreSQL Requirements

PostgreSQL is the central persistence layer.

Use SQLAlchemy, Alembic, and psycopg.

Suggested tables:

- `agent_runs`
- `agent_run_steps`
- `agent_messages`
- `investigation_plans`
- `agent_tool_calls`
- `generated_reports`
- `human_review_events`

Link workflow runs to:

- ML experiment IDs
- Model versions
- RAG query IDs
- Evidence IDs
- Validation run IDs

Use JSONB for structured workflow state where appropriate, while keeping important relationships in relational columns.

No SQLite.

## 13. Acceptance Criteria

- User queries produce structured investigation plans.
- Relevant ML tools are called according to the plan.
- RAG retrieval preserves source references.
- Evidence is registered in the Evidence Ledger.
- Report claims link to evidence.
- Checker validates reports before finalization.
- Unsupported reports can be routed for review.
- Workflow errors and tool calls are logged.
- SQL access is controlled and parameterized.
- Workflow run metadata is stored in PostgreSQL.
- No SQLite dependency exists.
